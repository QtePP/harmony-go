# 护城河加深方案（2026-11-25）

> 前置结论见 [`docs/OPENBITFUN-COMPARISON.md`](OPENBITFUN-COMPARISON.md)：
> OpenBitFun 用「主机 + 遥控器」拿走广度，我们用「端侧运行时」守深度。
> 本文回答一个问题：**接下来 6 个月，把力气花在哪，才能让「换掉 HarmonyGo」变得越来越贵。**
>
> 这是一份可执行提案，不是承诺。所有目标都带真机验收与 kill criteria；
> 没有设备证据的项，一律标「未验证」。

---

## 0. 先看结论

### 三个主攻（真正的护城河）

1. **Ontology 2.0 —— 记忆护城河**：从「模型记得调用工具」变成「越用越懂你、可溯源、
   可带走、只在本机」。**用得越久，换走的代价越大。**
2. **Continuity 2.0 —— 多设备护城河**：手机 / 平板 / 2in1 是**一套工作区**，不是三个 App；
   换设备不换会话，且不需要账号。
3. **Artifact Studio —— 场景护城河**：把「聊完了」变成「交付了」——端侧产物有库、有版本、
   有模板、可直接发；并用本体自动填掉重复信息。

### 三个地基（不做就会被绕过）

4. **Footprint**：设备占用 **~2.1GB → ≤1.8GB**（先删 229MB 副本，再裁 300MB）；HAP **388MB → ≤310MB**；首装解包 ≤75s。
5. **Trust Console**：看得到每一次联网；敏感记忆字段加密；「无账号、无遥测」可验证。
6. **Ecosystem**：MCP + 中英双语；不追市场，只补「没有就会被换走」的缺口。

### 5 天快赢（立刻可做，真机可验）

| # | 动作 | 收益 | 成本 |
|---|---|---|---|
| 1 | 解包后删掉沙箱里的 `payload.zip` 副本（`Payload.ets`） | 设备 **−229MB** | 0.5 天 |
| 2 | 对话里显示「本轮用了 N 条记忆」，点开可溯源 | 让护城河**可见** | 2 天 |
| 3 | 分享 docx / pdf / xlsx 进 App，直接开问（现在只收文本/图片） | 把系统分享变成入口 | 2 天 |
| 4 | pybot 移出默认包（实验能力，非产品） | HAP **−12MB** | 0.5 天 |
| 5 | 设置页加「存储占用」面板 | 让 2.1GB 可解释、可下降 | 1 天 |

**北极星**：30 日内回访、且完成过 ≥1 次任务的设备数。
**护城河指标**：每设备 pinned 事实数 / 双设备用户占比 / 每周产物数。

## 1. 判据：什么才算护城河

不是「功能多」，而是同时满足这四问：

| 判据 | 问题 | 不满足的后果 |
|---|---|---|
| **数据重力** | 用得越久，换走的代价越大？ | 用户随时可以换一个壳 |
| **结构不可替代** | 竞品靠加功能 / 加服务器能补上吗？ | 被「主机 + 遥控器」用更小安装包绕过 |
| **30 秒可感知** | 新用户第一次用就能感觉到？ | 价值只存在于文档里 |
| **6–12 个月难复制** | 不是一周就能抄的 UI？ | 变成功能竞赛 |

按这四问打分（1–5）：

| 方向 | 数据重力 | 不可替代 | 可感知 | 难复制 | 结论 |
|---|---|---|---|---|---|
| Ontology 2.0 | 5 | 4 | 5 | 4 | **主攻** |
| Continuity 2.0 | 4 | 5 | 4 | 3 | **主攻** |
| Artifact Studio | 3 | 3 | 5 | 2 | **主攻（场景）** |
| Footprint | 1 | 3 | 5 | 2 | 地基 |
| Trust Console | 2 | 4 | 4 | 3 | 地基 |
| MCP / i18n | 1 | 1 | 3 | 1 | 地基 |

> 一句话：**主攻选「越用越值钱 + 竞品结构上做不到」；地基选「不做就会被绕过」。**
> 两者都不满足的，不做。

## 2. 现状盘点：我们手里有什么、欠什么

### 2.1 资产（别人短期拿不走）

| 资产 | 证据 |
|---|---|
| 同进程 Node 24 + dsh 0.2.2，33 个工具、11 个自研插件 | `AGENTS.md` §2/§7.1 |
| 端侧本体：SQLite、23 谓词、pinned 注入、面板、bundle 合并 | `docs/ONTOLOGY.md`、`@ohos/dsh-ontology` |
| 端侧 Office / HTML A2UI / 纯 JS git / Pyodide | `docs/OFFICE.md`、`docs/HTML-COMPONENTS.md`、`docs/PYTHON.md` |
| 星闪 / TCP 同步（文件 + 会话 + 本体 bundle） | `docs/PROJECT-SYNC.md` |
| 无账号、无后端、模型 API 直连 | `docs/POSITIONING.md` |
| 系统分享入站（文本/图片）、语音、通知、六主题 | `ShareInbox.ets`、`module.json5` |

### 2.2 负债（会直接削弱护城河）

| 负债 | 量化 | 后果 |
|---|---|---|
| 设备占用高 | 系统口径 **2.10GB**（安装包 390MB + 应用数据 1.72GB，含 210MB 缓存）；沙箱里另有 `payload.zip` 副本 229MB（2026-11-25 已由 `Payload.ets` 删除） | 装完就占 2GB+，用户先被吓退 |
| API 26 起 | `compatibleSdkVersion: 26.0.0` | 放弃 HarmonyOS 6.x 一整代设备 |
| 记忆靠模型自觉 | 现行 `ontology` 是工具，模型不调用就不记 | 护城河「不自动变深」 |
| 同步明文、无续传 | `docs/PROJECT-SYNC.md` §7 | 跨设备价值打折，隐私叙事有洞 |
| 无 i18n / 无 MCP | 中文硬编码；`mcpServers` 恒空 | 被「功能齐全」的竞品比下去 |
| 2in1 未验 | `docs/POSITIONING.md` §10 | 鸿蒙 PC 红利拿不到 |
| 无本地指标 | 无遥测（这是优点），但也没有度量 | 不知道护城河有没有变深 |

### 2.3 一个战略判断

**技术壁垒会衰减，数据和场景壁垒不会。**
同进程 Node 这件事，dsh 上游或华为平台一次更新就可能商品化；
但「你的记忆、你的产物、你的设备配对」不会因为上游更新而搬走。
所以资源要压在**数据重力**和**场景**上，而不是继续堆运行时技巧。

## 3. 主攻 1：Ontology 2.0 —— 让记忆成为迁移成本

### 3.1 现状与缺口

现在能做：12 个动作（含 `propose` / `describe` / `related` / `metric`）、23 个受控谓词、pinned 才注入、
时间模型 v3、`v_live_fact`/`v_entity_edge`、`source_kind`/`source_ref` 血缘、`search` 覆盖度、
导入冲突报告、确定性自动抽取 → 面板待确认、面板查看/删除/最近删除、bundle 导出导入、星闪/WiFi 合并。

四个缺口：

1. **捕获**：已有 `remember`（显式）+ 规则式自动抽取（只认一阶明确句式，候选制）；
   还缺模型抽取/指代消解（“她对虾过敏”）与更多谓词覆盖。
2. **范围**：没有 global / project 两级；工作事实和身份事实混在一起。
3. **溯源**：v3 已记 `source_kind`/`source_ref`（会话 id、bundle 名、AGENTS.md），面板能显示
   “来自该会话/同步包”；但还不能点回原消息/轮次，也没有“这条是模型推断、待确认”的队列。
4. **带走**：bundle 是明文 JSON；换设备/备份时个人数据裸奔。

### 3.2 四个动作

**A. 捕获三通道**

- **显式**（已有）：`ontology.remember`。
- **半自动**（新）：消息长按 →「记住这条」→ 预填谓词/值 → 用户确认。
- **自动**（新，默认关）：回合结束后一次轻量抽取，只产出**候选**，不直接写；
  用户在「待确认」里一键接受/忽略。走同一模型，token 记进 context-ledger。

> 关键设计：**自动抽取永远不直接写库**。记忆写错比不写更伤信任；
> 候选制把「模型猜」变成「用户确认」。

**B. 范围与生命周期**

- `global`（跨项目：身份/语言/过敏/沟通偏好）与 `project`（项目事实）两级；
- 单值谓词沿用 `valid_from` 时间模型（已有）；
- 加「复审提醒」：超过 N 个月未确认的 `note` 标黄，不自动删；
- 冲突展示「旧值 → 新值 + 时间」，不静默覆盖。

**C. 可带走（加密 bundle）**

- 导出：`bundle.json` → scrypt(pairing code) → AES-256-GCM；
- 导入：输口令 → 解密 → 走现有合并规则（单值按 `valid_from` 新者胜，tombstone 传播）；
- 错误口令/截断文件明确报错，不半写。

**D. 可见与可信**

- 每轮 assistant 消息下加 chip：「本轮用了 3 条记忆」；点开显示来源会话/轮次/时间；
- 面板加「为什么它知道」：来源、置信度、最后一次确认；
- 字段级加密 spike：敏感谓词（身份/过敏/疾病）值加密，密钥经 HUKS 包裹；
  **若 3 天内跑不通，退化为「只加密导出 bundle」**，不阻塞主线。

### 3.3 验收（真机）

1. 新会话**不调用任何工具**，答出 3 条 pinned 事实（姓名/过敏/语言）。
2. 每条事实可点回来源会话；删除后新会话不再说。
3. 手机导出加密 bundle → 平板导入（输口令）→ 合并正确；错口令明确报错。
4. 长按消息「记住这条」→ 面板出现 → 下一会话生效。
5. 关闭自动抽取时，token 账本无额外增量。

### 3.4 指标

- 每设备 pinned 事实 ≥5（内测 4 周）；
- 注入命中率（有记忆的轮次 / 总轮次）≥30%；
- 用户纠正率 <10%；
- 加密 bundle 导出/导入各 ≥1 次/月（内测）。

### 3.5 成本与风险

- **8–12 人日**。
- 风险：自动抽取误报/成本 → 默认关、候选制、可撤销、token 可见。
- 风险：HUKS 字段加密复杂 → 3 天 timebox，失败降级。

## 4. 主攻 2：Continuity 2.0 —— 换设备不换会话

### 4.1 现状与缺口

现在能做：TCP / 星闪两条传输、manifest + 分片 + staging 原子落盘 + 配对码、
文件 + 会话 + 本体 bundle、不覆盖、不自动进模型。

缺口（`docs/PROJECT-SYNC.md` §7 自己写了）：

- **明文**：同局域网可被抓包；
- **无断点续传**：断一次从头传；
- **无 handoff**：传过去不等于能在另一台继续聊；
- **无发现**：每次手动配对。

### 4.2 四个动作

**A. 加密（无账号）**

- 配对码 → `scrypt` → 每分片 AES-256-GCM；
- 头部带协议版本与 nonce；不引入账号/云端；
- 兼容 v1：v2 只在双方都支持时启用，旧端回退明文并提示。

**B. 断点续传**

- 每文件/每分片 checkpoint（manifest id + offset + hash）；
- 断线后从最后 ack 继续；重复分片幂等；
- 失败保留半成品目录，下一次续传，不从头建。

**C. Handoff（真正的「换设备」）**

- 同步完成后给「在另一台设备继续」按钮；
- 深链打开同一 session id + cwd；先校验目标设备有该 workspace；
- 冲突策略：同一 session 只允许一台设备写入（租约/时间戳），
  另一台进入只读并提示「已在 X 上继续」。

**D. 发现与 2in1**

- 附近设备发现（UDP 广播或星闪）**默认关闭**，用户主动开；
- 发现不授予任何权限，仍需配对码（守住 `docs/INTEROP-PRODUCT.md` 四条红线）；
- 2in1 纳入同一工作区：键盘快捷键、拖拽、三栏；先用官方模拟器，真机另记。

### 4.3 验收（真机）

1. 手机 → 平板 100MB 工作区，传到 43% 断网，恢复后续传成功，MD5 一致。
2. 抓包看不到文件内容明文（只看到长度/时序）。
3. 手机同步一个会话 → 平板点「继续」→ 历史在、能接着发 prompt。
4. 两台同时打开同一会话 → 一台只读并提示，不双写。
5. 发现默认关；打开后仍需配对码。

### 4.4 指标

- 双设备用户占比 ≥20%（内测）；
- handoff 成功率 ≥95%；
- 续传成功率 ≥90%；
- 明文内容 0（抓包验收）。

### 4.5 成本与风险

- **15–20 人日**。
- 风险：鸿蒙后台/网络限制、星闪吞吐；必要时先做 WiFi，星闪只传小包。
- 风险：协议不兼容；v2 必须可回退。

## 5. 主攻 3：Artifact Studio —— 把「聊完了」变成「交付了」

### 5.1 现状与缺口

现在能做：HTML A2UI 组件库 + 整页长图/PDF、docx/xlsx 读写、App 内原生预览、
系统分享、长按分享文件。

缺口：**产物没有库、没有版本、没有模板、没有「一键交付」**；
每次都要重新描述，产物散落在 workspace 里。

### 5.2 四个动作

**A. ArtifactStore（产物库）**

- 索引：id / 类型 / 标题 / 项目 / 时间 / 版本 / 来源轮次；
- 版本：覆盖前留快照，可回滚；
- 入口：设置或会话侧栏「产物」；空态给模板。

**B. 模板（端侧、零外链）**

- 周报、会议纪要、发票/报销、简历、方案书；
- HTML 模板走现有 A2UI 组件库；Office 模板走 `office_write_docx/xlsx`；
- 模板 = 结构 + 占位符，不是固定文案。

**C. 一键交付**

- 会话里说「把这次对话变成周报」→ 提纲 → 填内容 → 预览 → 分享；
- 用 Ontology 自动填「姓名/角色/项目」等重复信息（**记忆 × 产物的组合护城河**）；
- 输出 docx / xlsx / html / pdf 任选，先预览再导出。

**D. 分享包**

- 产物 + Markdown 说明 + 资源打 zip；可选加密（复用 M2 的口令加密）；
- 另一台设备导入后可在产物库打开。

### 5.3 验收（真机）

1. 从同一段对话分别产出 docx、xlsx、html 各 1 份，App 内可预览。
2. 修改后覆盖，旧版本可回滚。
3. 模板产出可编辑（不是图片）。
4. 分享包在另一台设备打开，产物完整。
5. 周报自动带上本体里的姓名/角色，不需要重复输入。

### 5.4 指标

- 每周产物 ≥1 / 活跃设备；
- 导出/分享率 ≥40%；
- 模板使用率 ≥30%（内测）。

### 5.5 成本与风险

- **10–15 人日**。
- 风险：模板质量参差 → 先做 3 个高频（周报/会议/简历），用真实任务验收。
- 风险：Office 版式限制 → 明确「简化版式」，不承诺 Word 级排版。

## 6. 地基 1：Footprint —— 先把 2.1GB 降下来

### 6.1 事实

按构建产物估算（**需在真机设置里核对**）：

| 组成 | 大小 | 说明 |
|---|---|---|
| HAP（含 rawfile 里的 `dsh-payload.zip` 与 Pyodide） | ≈388MB（signed） | 2026-11-25 构建 |
| 沙箱 `filesDir/payload.zip` 副本 | ≈229MB | 旧版本 `Payload.ets` 复制后**从未删除**；2026-11-25 起解包成功即删除 |
| 沙箱解包 `filesDir/payload` | ≈1.4GB | Node 运行必需；`du` 实测 1,507,045 KB |
| 会话 + 工作区 + 缓存 | ≈90MB + 系统缓存 210MB | 应用数据里含缓存 |
| **系统口径合计（删副本后）** | **≈2.10GB** | `storageStatistics`：安装包 390.3MB + 应用数据 1.72GB |

### 6.2 四步

**A. 删副本（0.5 天）**

`zlib.decompressFile` 成功后删除 `payload.zip`；失败保留供诊断；旧版本遗留的副本在下次 `ensure()` 的幂等路径上也会被清掉。
**实测（2026-11-25 CMM-AL10）：`payload.zip` 已消失，设备占用 −229MB**，无行为变化。

**B. 按 profile 闭包裁剪（3–5 天）**

- 现在 337 个 `@deepseek-ai/*` 包、782MB（未压缩），其中大量 `client-ui-*`、
  `web-frontend`、`experimental-*` 在 ACP profile 下不可达；
- 先做静态闭包扫描，再按「可疑包」分批裁剪，每批用 **boot smoke + ACP 初始化 +
  `tools(33)` + 六个插件单测** 证伪；
- 目标：未压缩 −300~500MB，zip −30~60MB（实测载荷未压缩 ≈1.5GB，比方案初稿的 1.0GB 大，裁剪空间也更大）。
- **保守原则**：宁可少裁，不可裁出「2 required plugins did not activate」。

**C. 可选包（1–2 天）**

- pybot 移出默认包（−12MB；它本来就不是产品能力）；
- Python/Pyodide 做成「首次使用时下载/导入」的可选包（−33MB HAP），
  默认关闭时完全不占；
- 先做 pybot，Python 可选包看 6.2B 的收益再决定。

**D. 存储面板（1 天）**

设置 → 存储：HAP / payload / workspace / sessions / exports / 缓存 分项；
「清理缓存」「重置载荷」按钮；显示「预计可释放」。

### 6.3 目标与验收

- 设备占用 **≤1.8GB**（从 ~2.1GB；第一步删副本已 −229MB，第二步裁 300~500MB）；
- HAP **≤310MB**（从 388MB；pybot −12MB、Python 可选包 −33MB、裁剪 zip −30~60MB）；
- 冷启 ≤8s（已解包）、首装 ≤75s；
- 裁剪后 boot smoke、ACP 9 方法、`tools(33)`、插件单测全绿。

### 6.4 风险

- 裁到运行时依赖 → 3 天内回滚，只保留 A（删副本）；
- 可选包需要下载源 → 不做也行，先做 pybot 移除。

## 7. 地基 2：Trust Console —— 让「数据不出设备」可验证

### 7.1 为什么

「无账号、无遥测」是我们的差异，但用户现在只能**相信**，不能**看见**。
把信任做成产品面，是竞品最难抄的部分之一（他们要抄就得放弃云端叙事）。

### 7.2 三个动作

**A. 网络出口账本（只读，先不拦截）**

- `fetch-shim.cjs` 已经接管 fetch；再加 `node:https` 钩子（只记录，不改行为）；
- 记录：时间、host、字节数、用途（模型/搜索/git/其它）、session id；
- 设置 →「网络出口」：按天/按 host 汇总，可清空；
- 验收：一次 `web_search` + 一次 `git clone`，账本条目与实际相符。

**B. 本地-only 模式（可选，默认关）**

- 只允许模型 API host，其它出站请求直接拒绝并给明确错误；
- 用户主动开启，开启时提示「web_search / git / 网页预览会不可用」；
- 这是「飞行模式」的产品化，不是默认行为。

**C. 加密与零遥测声明**

- 敏感本体字段加密（与 M1 共用 HUKS spike）；
- 加密导出 bundle / 分享包；
- README/设置里写清「我们不收集什么」，并给出可复现的验证方法。

### 7.3 验收

1. 账本覆盖 fetch 与 https 两条路径；漏记率可解释。
2. 本地-only 开启后 `git clone` 被拒且文案清楚；模型对话不受影响。
3. 设置页有一页「数据去哪了」，不需要读文档。

### 7.4 成本与风险

- **8–12 人日**。
- 风险：patch `node:https` 影响 dsh → 先只读记录，出问题可一键关；
- 风险：加密影响启动 → 只加密导出，不动 live DB。

## 11. 不做什么（明确的反范围）

| 不做 | 原因 |
|---|---|
| Relay / 账号 / 应用市场 | 与「无账号、数据不出设备」正面冲突；也是 OpenBitFun 的战场 |
| Desktop / CLI / Web 客户端 | 广度追不平，且会稀释端侧投入 |
| 多智能体编排 UI | dsh `subagent` 已够用；先做记忆和连续性 |
| Computer use / 桌宠 / 悬浮窗 | 权限与审核成本高，不是我们的场景 |
| 三端 KMP 共享 | 我们只有鸿蒙，收益为负 |
| 全量 i18n / 插件市场 | 先做中英与 MCP，不铺生态 |
| 为降体积改 dsh 源码 | 上游升级即腐化；只做装配期裁剪 |
