# 三条端到端验收（手工执行）

> 目的：用**三条情境**覆盖全部可感知能力——本体 / Python / HTML / Office / 导出分享 /
> 纯 JS git / 语音输入与朗读 / 图片多模态 / 项目同步（文件 + 会话 + 本体 bundle）/ 星闪与 WiFi。
> 每条都给**固定的用户口吻提示词**和**可勾选的验收点**；本文不替用户执行。
>
> 设备：手机 CMM-AL10（单栏）与平板 MLR-AL00（双栏）；需要双机的情境已标注。

## 0. 前置（一次配好）

| 项 | 要求 | 不配的后果 |
|---|---|---|
| 对话协议 | 设置 → 对话协议 = **ACP**（首启引导里选过就够） | 图片输入会提示「SDK 通道暂不支持图片输入」；纯 JS 搜索/凭据热更新也不挂载 |
| Python | 设置 →「Python 运行时（实验）」开 → **彻底退出并重开** | 关闭时 `tools(31)`、开启后 `tools(33)`；没有 `python_run`，模型只能心算（必须如实说明） |
| 麦克风 | 首次点输入框左侧麦克风时授予权限 | 语音按钮不出现或点了没反应 |
| 语音引擎 | 离线识别可用（设置 → 诊断里语音状态正常；不行就在设置里点「重试」） | 录音后输入框没有文字 |
| GitHub Token | 设置 →「GitHub Token（用于 git push）」填 fine-grained token（仅参考仓库 Contents 读写） | 情境 B 只能 commit，push 返回 `GIT_NO_TOKEN` |
| 双机 | 同一 WiFi 网段，或两台都开星闪；同步时一台「发送」、另一台「接收」，报 6 位配对码 | 同步页面扫不到设备 |
| 素材 | ① 情境 A 的饮食记录 CSV 文本（见下）；② 情境 B 的**报错截图**提前存进相册 | 情境 B 的多模态步骤无法执行 |

## 1. 情境 A｜生活管家（单机）

**新建项目「生活管家」。**

### A1 语音写入本体

点输入框左侧 **麦克风**，说：

> 记住：我叫林舟，对花生过敏，沟通上先给结论再给细节。

说完松手，**输入框应出现识别出的文字**，再点发送。

验收：

- [ ] 输入框里出现正确中文（不是空白、不是乱码）；
- [ ] 设置 →「它知道什么」出现 3 条事实：姓名、过敏、沟通偏好；
- [ ] 其中身份/过敏属于**硬约束**（面板可见「硬约束」计数）。

### A2 Python 真算 + HTML 页面

发：

```text
这是我的饮食记录：
日期,蛋白质,训练完成
周一,110,1
周二,95,0
周三,120,1
周四,105,1
周五,130,1
周六,88,0
周日,115,1

用 Python 真算平均蛋白质和训练完成率（必须调用 python_run / pandas，不要心算），
再生成一页 life-week.html：顶部数字卡、一个环形进度、一个训练完成柱状图，
手机优先、零外链，最后 check。
```

验收：

- [ ] 工具轨迹里出现 `python_run`，stdout 有 pandas 的汇总；
- [ ] 回答里的平均蛋白质 / 完成率与 stdout 一致（不是编的）；
- [ ] `life-week.html` 出现在产物面板，可预览；`check` 无外链错误。

### A3 导出与分享

在 HTML 预览页点右上「导出」：

- [ ] 菜单有三项：**导出长图（亮 + 暗）** / 导出为长图 PNG / 导出为 PDF；
- [ ] 点「亮 + 暗」→ 生成两张同尺寸长图（文件名带「亮」「暗」），分享面板弹出；
- [ ] 点「导出为 PDF」→ 生成单页 PDF，可分享。

### A4 语音朗读

长按一条回复 →「朗读」。

- [ ] 设备出声朗读该回复（无需耳机）。

## 2. 情境 B｜故障急救（双机：图片多模态 + git + 同步）

**新建项目「故障急救」。** 先在相册里准备一张报错截图（可以是任意运行时报错页面）。

### B1 图片多模态：让它读截图

点输入框右侧 **图片按钮** → 从相册选那张报错截图 → 输入：

> 这页报错你看一下，错误码是多少？先告诉我错误码和发生在哪个环节，不要猜。

验收：

- [ ] 消息里出现图片缩略图（可点开全屏）；
- [ ] 模型回答引用了**截图里的真实文字/错误码**（拿截图对照）；
- [ ] 轨迹里能看到图片作为输入被处理（不是把文件名当文本猜）。

### B2 git：定位、修复、提交

接着发：

> 这个仓库 <owner/repo> 里就是这个报错，帮我定位根因、做最小修复并提交。
> 修完生成一页 rescue-report.html（排查步骤、表格：错误码/位置/根因/修复、一条预防建议），并 check。

验收：

- [ ] 轨迹：`git snapshot/clone → grep → read → edit → commit`（有 token 时最后 `push`）；
- [ ] 回答给了 **commit hash**；没有 token 时明确说 `GIT_NO_TOKEN` 而不是假装成功；
- [ ] `rescue-report.html` 可预览，`check` 通过。

### B3 端到端同步：文件 + 会话

同一项目里发：

> 把项目文件和历史会话一起发到我的平板上。

平板点「接收」，输入手机上显示的 6 位配对码（传输可在 **星闪 / WiFi 直连** 间切换）。

验收：

- [ ] 手机端进度到 100%，平板端显示接收文件数；
- [ ] 平板「项目文件」里出现 `rescue-report.html`；
- [ ] 平板的会话列表出现同步来的会话，点开有历史消息、可继续提问；
- [ ] 切换星闪/WiFi 各试一次（任一条成功即可，记录用了哪条）。

## 3. 情境 C｜办公周报（双机：Office + 本体跨设备）

**新建项目「办公周报」。**

### C1 周报与台账

发：

```text
帮我出本周周报。内容按这些来：
- 修了项目同步的配对码超时问题，改了 sync 的两个文件；
- 补了本体时间模型文档；
- 评审了两个 PR。
Word 版发领导（结论 → 完成项 → 问题 → 下周计划），Excel 台账留底（日期/项目/类型/内容/文件数/耗时/状态），
工时合计用 Python 汇总，不要心算。
```

验收：

- [ ] `周报-*.docx`、`工作量台账.xlsx` 出现在产物里；
- [ ] **App 内直接打开**（原生预览：docx 标题/段落/表格；xlsx 工作表、列号、数字右对齐），不跳外部 Office；
- [ ] 轨迹有 `python_run`，工时合计与 xlsx 一致。

### C2 页面与导出

发：`再出一页本周概览 html，我要发群里。`

- [ ] 页面可预览；导出长图/PDF 可用（同 A3）。

### C3 本体跨设备同步

发：`记住：以后周报都按「结论 → 完成项 → 问题 → 下周计划」这个结构写。`

然后在「项目同步」里**只勾 `ontology`**，发送到另一台设备；对方面板点「导入最新同步包」。

验收：

- [ ] 两台设备「它知道什么」里事实条数一致；
- [ ] 另一台设备**新会话零工具**复述出「周报结构」这条偏好（问：周报按什么结构写？）；
- [ ] 只同步本体时，项目文件没有被一起传过去（与 B3 的「全部文件 + 会话」对比）。
